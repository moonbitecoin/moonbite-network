REST API

Query the chain in one line

The public seed node exposes a read-only JSON API. No API key, no account — just HTTP. All responses follow the same {"status": "success", ...} envelope.

# Network status — chain height, peer count, sync state
curl https://moonbite.org/api/status

# Latest block
curl https://moonbite.org/api/block/latest

# Block by height
curl https://moonbite.org/api/block/1000

# Transaction by txid
curl https://moonbite.org/api/tx/<txid>

# Address balance & history
curl https://moonbite.org/api/address/moon1youraddresshere

The full endpoint list, request/response shapes, and error codes are documented in the developer reference.

Contributing

How to contribute

MoonBite follows a standard open-source contribution model. Here's the short version.

🍴

Fork & clone

Fork the repository on GitHub, clone your fork locally, and create a feature branch. Keep branches focused — one concern per pull request.

🧪

Run the tests

The repo includes a test suite. Run it before and after your change. A patch that breaks existing tests won't be merged. New functionality should come with new tests.

📝

Open a pull request

Describe what the change does and why. Reference any related issue. A concise, honest PR description gets reviewed faster than a vague one.

🐛

File bugs

If you find something wrong, open a GitHub issue with a clear reproduction case. Include the platform, node version, and exact steps that trigger the bug.

📖

Improve docs

Documentation PRs are just as welcome as code PRs. Clearer setup guides, better API examples, and corrected errors all have real value.

🔍

Review open PRs

Reviewing someone else's pull request — finding edge cases, checking the logic, testing it locally — is one of the most useful things a contributor can do.
