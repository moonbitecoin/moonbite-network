What it is

The reference implementation

MoonBite Core is the authoritative software that defines what the MoonBite network is. Built on the Litecoin-lineage codebase — itself descended from Bitcoin Core — it carries decades of peer-reviewed cryptographic engineering.

⛓️

Litecoin lineage

MoonBite Core forks from the Litecoin Core codebase, which descends from Bitcoin Core. The consensus rules, cryptographic primitives, and peer protocol are battle-tested across years of mainnet operation.

📜

Defines the rules

Every MBITE parameter lives in this code: the 10 MBITE genesis reward, the 1,000,000-block halving schedule, the 2.5-minute block target, and the 19,999,999.87 MBITE cap. The software is the spec.

🔓

Fully open source

Every line of consensus-critical code is public. You can read it, build it from source, and run it without trusting a binary published by anyone — including the MoonBite team.

What it does

What your node actually does

When you run MoonBite Core, you become an independent participant in the network — not a passive observer.

✅

Validate every block

Your node checks every transaction in every block against the full ruleset: signatures, script, supply schedule, double-spend protection. Nothing gets through unchecked.

📡

Relay to peers

Your node propagates valid blocks and transactions to the rest of the network. More nodes means faster propagation and a more resilient mesh — harder to silence or split.

🔌

Serve the RPC interface

MoonBite Core exposes a JSON-RPC API on localhost. Wallets, miners, and custom tools use it to read chain state, submit transactions, and query address history.

🧱

Maintain the UTXO set

Every unspent coin output since genesis is tracked in a local database. When you receive MBITE, your node already knows — it doesn't have to ask a third-party server.

🧮

Enforce the supply cap

No node in the network — not even one run by the MoonBite developers — can create coins beyond the schedule. Your node would reject such a block outright.

🕵️

Index for the explorer

The block explorer on this site reads from a MoonBite Core node via RPC. Run your own node and you can query the same data without relying on this service at all.

Why run your own

The case for running a node

Every full node you trust instead of running yourself is a point of trust. Trust compounds. Running your own node removes the entire layer.

🏠

Sovereignty

When your wallet connects to your own node, your transaction history and address balances never leave your machine. A third-party node can see every address you query.

🛡️

Security

A malicious or compromised public node could serve you a fake chain tip. Your own node compares proof-of-work directly — it cannot be tricked by a crafted response.

🌐

Strengthening the network

Each additional full node raises the cost of a network partition or eclipse attack. Running a node is the most direct contribution you can make to decentralisation.

⚖️

Voting with your node

If a future upgrade is ever controversial, nodes that reject it are a real signal. Full-node operators are the ultimate check on protocol changes — no miner or developer can override them.

Quick start

Starting a node and hitting the API

Once you have the daemon binary (see download notes), starting a testnet node is a single command. The RPC is then available on localhost.

Start the node

# start moonbited on testnet
moonbited -testnet \
  -daemon \
  -rpcuser=rpcuser \
  -rpcpassword=rpcpass

# watch it sync
moonbite-cli -testnet getblockchaininfo

Query the read-only REST API

# chain tip via the web API
curl https://moonbite.org/api/blockchain/info

# response
{
  "status": "success",
  "height": 4210,
  "tip_hash": "0000…",
  "total_money_coins": 42100
}
